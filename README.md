# itsmesujan

Multi-page 3D portfolio for Sujan Majhi (`itsmesujan`) — built from scratch as a
new system, not derived from the earlier `itsmesujan-3d` Next.js build.

## Stack

- **Vite 7** + **React 19** + **TypeScript** (strict, no `any` escapes)
- **React Three Fiber 9** / **three 0.180** — all 3D
- **GSAP 3.14** + **ScrollTrigger** — scroll choreography
- **Lenis 1.3** — one smooth-scroll clock, driven by GSAP's ticker
- No UI framework, no CSS framework, no component library

## Routes

| Route         | What it is                                                      |
| ------------- | --------------------------------------------------------------- |
| `/`           | Scroll-driven hero; the monolith is the subject, not decoration |
| `/work`       | Filterable project index over real repositories                 |
| `/work/:slug` | Case study: problem → mechanism → what was built                |
| `/lab`        | A real shader experiment with a working parameter                |
| `/about`      | Principles and stack                                             |
| `/contact`    | Mail-compose form (no server, and the UI says so)               |

## Art direction

Carbon void, bone paper, one signal orange.

- `--signal: #ff4d1c` is a **light** token only (glows, 3px+ rules, embers).
- `--signal-ink: #cc380a` is the **text** orange — 5.4:1 on `--void`, passes AA.
- `--verify: #34c77b` marks open-source state — 8.4:1 on void.

Never use `--signal` for small text; use `--signal-ink`.

## Imagery

All stills are generated by `scripts/gen-assets.py` through Agnes AI
(`agnes-image-2.5-flash`) into `public/media/`.

**The endpoint has a size whitelist and silently ignores anything off it.**
This is not documented, and it is the reason the first version of this site's
images were soft: the script asked for `1200x900` and received `1152x864`.
Measured with `scripts/probe-sizes.py`:

| requested | returned |
| --------- | -------- |
| `4096x4096` | `4096x4096` exact |
| `2048x2048` | `2048x2048` exact |
| `3840x2160` | `3845x2157` (true 4K) |
| `1200x900` | `1152x864` downgraded |
| `1536x1024` | `1248x832` downgraded |
| `1920x1080` | `1312x736` downgraded |
| `2560x1440` | `1312x736` downgraded |
| `1536x1536` | `1024x1024` downgraded |

So the pipeline generates **4096x4096 masters**, verifies the returned
dimensions instead of trusting the request, centre-crops to the aspect the
design uses, then LANCZOS-downscales to a web weight. Masters are written to
`.masters/` (gitignored) and deleted unless `--keep` is passed, so a
re-shoot at a different size costs no API calls.

```bash
pnpm assets                      # only missing or wrong-sized files
pnpm assets -- --force           # regenerate everything
pnpm assets -- --keep            # retain the 4K masters
python scripts/probe-sizes.py 4096x4096   # re-measure the whitelist
```

Prompts encode one palette so the set stays coherent. If you add an asset,
check its requested size against the table above first.

## The hero: a mission graph, not a monolith

`src/three/Topology.tsx` is the site's single visual idea. The brief was one
strong concept rather than five competing ones, and the concept chosen was the
one the copy already argues: *systems that show their work*. So the hero is a
system — a layered DAG with a pulse head travelling the selected route.

It is deliberately cheap, because a janky hero is worse than a plain one:

- every node in **one** `InstancedMesh`, every edge in **one** `LineSegments`
  — two draw calls regardless of graph size
- instance matrices written **once** in a layout effect, never per frame
- the pulse is a uniform, so a frame costs two uniform writes
- zero allocation inside `useFrame`
- procedural scatter comes from `src/three/random.ts`, a pure function of
  `(seed, index)`. A stateful PRNG inside a `useMemo` silently regenerates on
  re-render; the sequence is sized `NODE_COUNT * 4` and throws if exhausted.

`src/three/Cinematic.tsx` adds bloom, chromatic aberration, vignette and film
grain. It is lazily imported so it stays out of the critical chunk, and the
whole stack is dropped on the low tier — postprocessing is the first thing to
cut when a device is struggling.

## Motion contract

One flag, `motion`, decides behaviour for the whole app. It is false when
`prefers-reduced-motion: reduce` is set **or** when the URL contains
`?static=1`. When false:

- Lenis is never constructed
- no ScrollTrigger scrubbing or pinning
- render loops stop (`frameloop="demand"`)
- the marquee stops and becomes scrollable

The static composition is designed, not a fallback bolted on. Every route
keeps all content, all links and all actions in that state.

## Performance rules held in code

- One `<Canvas>` per route. Card hover previews mount only on hover, so at
  most one card context exists at a time.
- DPR capped at 2 (1.5 on compact/low-memory).
- No shadow maps. Post-processing only on the hero, and only above the low tier.
- `?static=1` is the QA entry point for the reduced-motion path.

## QA

Four puppeteer harnesses, all run against `pnpm preview`:

```bash
node scripts/visual-qa.mjs      http://localhost:4173   # 21 route x viewport checks
node scripts/boot-probe.mjs     http://localhost:4173   # boot overlay must unmount
node scripts/fallback-qa.mjs    http://localhost:4173   # no-webgl / reduced-motion
node scripts/interaction-qa.mjs http://localhost:4173   # keyboard, filters, forms, SEO
node scripts/focus-probe.mjs    http://localhost:4173   # tab order per route
```

Two traps worth knowing if you extend them:

- **Never filter focusable elements on `offsetParent`.** It is null for every
  `position: fixed` element, which is exactly how the skip link is hidden, so
  the skip link silently disappears from the audit. Use `getClientRects()`.
- **Headless Chrome's focus wrap emits `document.activeElement === body`**
  before arriving at the first stop. That is a property of the driver, not a
  hole in the page's focus order — read the DOM tab order instead of counting
  Tab presses.
